# EduCore V1.1 源码审查与交付记录

审查范围：Java/Spring 服务、MyBatis Mapper、Flyway 迁移、自动化测试、Vue 页面、环境配置、消息/缓存实现和部署文档。先根据 V1.0 实际源码和测试核对已有功能，再补齐 V1.1 缺口。本报告将可复现的缺陷与尚未实跑的环境能力分开记录。

## 优先级问题清单

### P0：数据一致性、安全或核心流程故障

| 问题 | 审查结论 | 修复与验证 |
| --- | --- | --- |
| 公网访问只使用 HTTP，账号凭据和业务数据未加密传输 | 云端当前由 80 端口提供演示服务，没有 TLS 终止 | 按用户明确要求暂不调整公网协议；此项仍是未关闭的 P0，不应使用真实或复用密码，也不作为生产环境部署 |
| 同一学生再次报名时并发处理过期的旧订单可能重复释放名额 | 创建订单路径发现旧待支付订单更新缺少针对性的锁定读；并发旧订单处理有重复调整容量风险 | 使用锁定读串行化当前学生待支付订单检查；集成测试覆盖过期订单替换后预占计数和 Outbox 数量 |
| 支付、取消和超时释放可能竞争同一订单 | 三条终态迁移已有订单行锁和状态门槛；检查后保留该设计 | 3 个报名集成场景覆盖重复支付、过期替换、同学生并发创建；先前 V1.0 本地 MySQL 联调覆盖基础报名支付链路 |
| 教师保存考勤可能与确认课次完成并发，造成完成后仍写考勤 | 深入检查结课流程时发现普通状态读取与确认操作没有互斥 | 考勤写入现在用 `SELECT ... FOR UPDATE` 锁课次；并发测试持有课次锁确认完成，校验等待中的考勤更新被拒绝 |

### P1：重要功能缺失或业务闭环不完整

| 问题 | 审查结论 | 修复与验证 |
| --- | --- | --- |
| 课次缺少“已完成”状态，无法形成课时与结课闭环 | V1.0 只有待上课和取消 | 新增 V6 Flyway `COMPLETED`；教师只有在课次结束且全员考勤完成后可确认；班级结课要求日期已到、至少一个计划课次、无未完成课次、无缺失考勤 |
| 管理员无法从班级查看教学成效 | 缺少课时、出勤、作业、考试分数及及格率聚合 | 新增管理员/负责教师班级分析 API 和页面；MySQL 聚合查询覆盖平均/最高/最低分、及格率、作业完成率、出勤率 |
| 学生没有单一的学习中心，管理员也缺少运营看板 | 看板 API 尚不存在 | 新增 `GET /api/students/me/dashboard`、`GET /api/admin/dashboard`；按身份过滤学生数据；所有订单金额标识为模拟金额；热门课程及当前报名排除结课班级 |
| 服务器部署和面试演示材料不足 | 只有本地启动文档；没有完整演示数据或讲解脚本 | 增加 Compose、Dockerfile、Nginx 配置、可重复执行的本地演示 SQL、三角色账号说明和四分钟演示脚本；云端部署验证见测试报告 |
| 新增结课状态没有自动化回归 | 原测试不验证考勤完整性、课次完成和班级结课门槛 | 新增课次完整考勤、结课门槛及并发锁测试；最终本地全套 33 个后端测试通过 |

### P2：展示、文档和结构改进

| 问题 | 修复与当前限制 |

| 审查域 | 本次源码结论 |
| --- | --- |
| 用户认证、角色和数据权限 | JWT 认证与 ADMIN/TEACHER/STUDENT 路由角色限制已存在；教师对象操作按服务端身份检查，学生查询按本人身份。V1.1 新看板做角色和数据范围集成测试。 |
| 课程、班级和教师分配 | 课程与教学班分离；一个班级关联课程和主讲教师；服务校验状态转换、容量和教师状态。 |
| 报名、订单、模拟支付、入班 | 订单预占容量，模拟支付事务内写流水并正式入班；终态幂等。补充过期订单锁与并发回归。 |
| 名额并发和超时释放 | 条件更新做原子占位，订单行锁串行终态，RabbitMQ 到期事件加 UTC 扫描补偿；V1.0 MySQL 压测记录见测试报告，V1.1 新发版未重复压测。 |
| 排课和考勤 | 教师、教室、班级固定顺序锁和冲突检查已有测试；V1.1 增加考勤写入与课次完成互斥。 |
| 作业发布、提交、批改 | 基础流程和唯一约束已有；修复教师端截止时间 UTC 处理；增加通知缺失扫描补偿，保留消费幂等。 |
| 题库、组卷、考试和成绩 | 题目/试卷快照、客观题阅卷、唯一尝试和超时收卷已实现；修复并发主观题评分的尝试总分竞争，并发测试验证只得到合并后成绩。 |

| Redis 缓存一致性 | Redis 只缓存课程详情，不作报名、权限事实；本次部署包含持久化失效队列和重试逻辑，Redis 容器正常运行；本次未在云端执行课程修改后的缓存故障恢复场景。 |
| 页面、接口联调和部署 | 三角色基础业务页面和 `/api` 前缀已核对；新增看板、教学分析、结课操作和 UI 加载优化。真实 MySQL 和云端 Compose API 通过演示数据联调。 |

## 本阶段已完成

1. 完成已修复的 P0 报名一致性/考勤互斥问题和 P1 业务闭环补齐，以及看板、分析、课次确认功能；公网 HTTP P0 按用户要求暂缓。
2. 更新 API、架构、数据库、业务规则、部署、测试报告、README 和项目演示脚本。
3. 提供本地演示数据初始化 SQL、三角色演示账号和容器化配置。
4. 最终后端 `mvn -q test`：33 个测试，0 失败、0 错误、0 跳过；`mvn -q package` 和前端 `npm run build` 通过。
5. 本机 MySQL 8.0.46 临时 schema 执行 V1–V6；云端 MySQL 8.4 执行 V1–V7。云端三种角色登录、三类看板、管理员审计列表和 OpenAPI 均经 Nginx 返回 200。临时本机 schema 与应用进程已清理。
