# EduCore 4 分钟项目演示脚本

## 开始前

执行 `docker compose up --build -d` 和 `./scripts/load-demo-data.ps1`，打开 `http://localhost`。使用 README 中的 `demo-admin`、`demo-teacher`、`demo-student` 角色账号；三者本地演示密码相同。下面页面名称以角色侧栏为准。

快速体验多角色数据时，可使用教师 `demo-teacher-02` 查看 Python 班、`demo-teacher-03` 查看英语班；学生 `demo-student-07` 有待支付订单，`demo-student-08` 有已批作业和考试成绩，`demo-student-10` 有待批作业。所有演示账号共享 README 中的演示密码。

## 0:00–0:35：产品和架构

**讲解**：EduCore 是面向培训机构的 Java 模块化单体，覆盖课程到班级教学的日常闭环。Java 21 / Spring Boot 3 提供 API，MyBatis-Plus 访问 MySQL，Redis 只缓存课程详情；RabbitMQ 用于订单超时与作业通知，消息事件先写 Outbox。

**展示**：登录页和管理员工作台导航。点出系统按角色提供管理员、教师和学生入口。

## 0:35–1:20：管理员运营和教学进度

**操作**：管理员进入“工作台”，查看学生数、在教班级、报名人数、模拟支付订单、本月报名、热门课程和班级课时出勤。

**讲解**：订单金额会显式标成模拟金额。班级教学情况和课程热度直接通过 MySQL 聚合查询得到。切到“班级管理”点一个班级的“教学分析”，查看考试分数、及格率、作业完成率和考勤率。

## 1:20–2:10：学生报名与模拟支付

**操作**：退出管理员，使用学生账号进入“课程与报名”，展开 Java 后端工程实践的开放班级，点击“报名并创建订单”，在确认框选择“模拟支付”；随后进入“我的班级”和“学习概览”。

**讲解**：下单时服务端在数据库事务中原子预占名额；模拟支付在订单锁内把预占转换成正式入班。重复请求、支付和过期释放都按订单状态做幂等保护。屏幕金额是演示值，不是真实支付。

## 2:10–3:05：教师考勤与课次结课

**操作**：退出学生，使用教师账号进入“工作台”；查看近期课表、待批作业、待批简答题和班级进度。点“去批改”处理一条提交，再进入“考勤登记”完成课次考勤。

**讲解**：教师只能操作自己负责的班级；缺少任何在读学生考勤或课次尚未结束时，后端都会拒绝完成。确认之后考勤记录锁定。管理员结课班级时还会检查结课日期、计划课时、考勤、已发布作业/考试和待批成绩。

> 演示种子里的下一课次安排在初始化时间之后 1 天。若要现场演示确认课次，可以将它改为已结束时间并重新运行相应考勤流程；不要通过直接改数据库绕过服务端校验。

## 3:05–4:00：作业、考试与工程质量

**操作**：教师查看作业提交、打开已完成考试的成绩；切换学生看最近成绩、未读通知、未来考试和即将截止的作业。回到教师可展示题库与待批简答题列表。

**讲解**：试卷发布时保存题目快照，学生 API 不返回答案；作答进度会定时写入服务端，刷新后可恢复。选择题服务端自动阅卷，主观题需要教师评分，评分并发时按答卷锁串行。操作审计记录写请求的操作者和结果，但不留存请求内容。演示结束可说明 H2 测试覆盖报名、排课、结课、草稿保存和看板权限；真实 MySQL 并发结果以最新测试报告为准。

## 收尾重点

用一句话总结：项目的价值在于把并发名额、支付状态转换、排课互斥、Outbox 消息和角色数据边界放进真实业务闭环，并用集成测试和看板界面展示结果。演示金额和演示账号只用于本地环境。
